# النسخ الاحتياطي التلقائي لمرتفعات ستور

هذا الإعداد يجهّز نسخة يومية مشفّرة من قاعدة بيانات Supabase ويرفعها إلى المسار الخاص `backups/` داخل Bucket ‏R2 باسم `mortafaat-store-media`. لا يجعل ملفات النسخ الاحتياطية عامة، ولا يغيّر بيانات المتجر.

## المطلوب مرة واحدة

### 1. إنشاء بيانات دخول R2 محدودة الصلاحية

من لوحة Cloudflare افتح R2 ثم **Manage R2 API Tokens** وأنشئ مفتاح S3 بصلاحية **Object Read & Write** على Bucket واحد فقط: `mortafaat-store-media`.

احتفظ بقيمتي **Access Key ID** و**Secret Access Key** في مكان آمن. لن نحتاج إلى إرسال أي منهما داخل المحادثة.

### 2. الحصول على رابط قاعدة البيانات

من لوحة Supabase للمشروع افتح **Connect**، واختر **Session pooler**، وانسخ Connection string. لا تستخدم رابط Transaction pooler لهذه المهمة.

### 3. إضافة أسرار GitHub

افتح المستودع على GitHub ثم:

**Settings → Secrets and variables → Actions → New repository secret**

أضف الأسماء التالية، وضع القيمة المناسبة لكل واحد:

| اسم السر | القيمة |
|---|---|
| `SUPABASE_DB_URL` | رابط اتصال قاعدة بيانات Supabase باستخدام Session pooler |
| `R2_ACCESS_KEY_ID` | Access Key ID من R2 |
| `R2_SECRET_ACCESS_KEY` | Secret Access Key من R2 |
| `BACKUP_ENCRYPTION_PASSPHRASE` | عبارة مرور قوية وفريدة لتشفير النسخ |

احتفظ بعبارة مرور التشفير في مدير كلمات مرور أو مكان آمن منفصل عن GitHub. من دونها لن يمكن فك تشفير النسخ لاحقًا. لا تضع الأسرار في ملفات المشروع أو المحادثات.

## طريقة العمل

- تشغيل تلقائي يوميًا الساعة 02:00 UTC.
- تصدير الأدوار والمخطط والبيانات باستخدام Supabase CLI.
- ضغط الملفات وتشفيرها بخوارزمية AES-256.
- رفع الملف المشفّر إلى `backups/YYYYMMDDTHHMMSSZ/database.tar.gz.gpg`.
- التحقق من وجود الملف بعد الرفع.
- حذف النسخ الأقدم من 30 يومًا بعد نجاح رفع النسخة الجديدة.
- فحص إجمالي حجم كل ملفات الـBucket يوميًا وإظهار تنبيه عند 8GB وتنبيه أقوى عند 9GB.
- إذا لم تُضف الأسرار الأربعة بعد، يتخطى التشغيل النسخ بدلًا من إنشاء ملف ناقص.

## تشغيل أول نسخة يدويًا

بعد إضافة الأسرار، افتح **Actions → Encrypted Supabase backup to Cloudflare R2 → Run workflow**. تأكد أن التشغيل اكتمل بنجاح، وأن خطوة الرفع والتحقق نجحت.

## الاستعادة

لا تستعد نسخة مباشرة فوق قاعدة الإنتاج. نزّل الملف المشفّر من R2، وفك تشفيره باستخدام عبارة المرور المحفوظة، ثم اختبر ملفات `roles.sql` و`schema.sql` و`data.sql` على مشروع Supabase منفصل أولًا. الاستعادة الكاملة تحتاج مراجعة توافق إصدار Postgres وإعدادات Supabase قبل التنفيذ.
